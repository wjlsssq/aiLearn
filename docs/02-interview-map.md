# 20 道面试题与功能映射

这些题目参考公开面经主题并按本项目原创改写。编号表示学习依赖顺序，不是面试出现频率排名。公开资料不构成统一样本的统计，不能据此声称某题有确定的考察概率。检索依据见 [资料来源](03-references.md)。

规则：一道主问题 Q 对应一个模块 M；追问与实验仍归在该模块。先修内容在阶段 0 补齐。每题后续形成独立课程文档、功能实现、逐行注释和面试卡。

## 第一阶段：模型与应用基础

### Q01 / M01：LangChain 解决什么问题，为什么不直接调用模型 API？

- **功能**：基础客服聊天；前端发送一句话，后端调用聊天模型并返回。
- **实现位置**：聊天输入区、聊天 API、模型工厂；对比供应商 SDK 与 LangChain 模型适配的最小调用。
- **重点**：模型适配、消息结构、API 边界；框架收益与额外抽象成本。
- **验收**：通过配置选择已验证的模型；分别演示正常回复与模型请求失败。
- **追问**：ChatModel 与普通文本生成接口有何差异？temperature 能否保证确定性？何时直接使用 SDK 更合适？
- **练习**：修改模型配置，指出哪些业务代码无需变更。

### Q02 / M02：如何设计可维护的 Prompt，消息角色有什么作用？

- **功能**：客服角色与语气配置、Prompt 预览。
- **实现位置**：角色配置区、Prompt 模板服务和模板版本。
- **重点**：system/user/assistant/tool 消息、模板变量、少样本、业务约束；角色优先级不等于权限控制。
- **验收**：同一问题切换“简洁”和“详细”配置；记录实际消息结构和输出变化。
- **追问**：模板变量缺失如何处理？用户文本能否覆盖服务端规则？Prompt 怎么做版本回归？
- **练习**：增加一个必填业务变量并验证缺失时的错误提示。

### Q03 / M03：LCEL / Runnable 如何组织调用，invoke、batch、stream 有什么区别？

- **功能**：问题规范化 → Prompt → 模型 → 文本解析的固定客服流水线。
- **实现位置**：流水线演示接口与步骤结果面板，使用 `langchain-core` 的相关组件。
- **重点**：输入输出契约、串联、并行、同步异步；固定流水线与 Agent 循环的关系。
- **验收**：能指出每一步的数据类型；批量处理两个独立问题；某一步异常能定位原因。
- **追问**：并行是否一定更快？异步与多线程有什么区别？流式能力是否能穿过所有步骤？
- **练习**：增加一个输入清洗步骤并解释它对后续步骤的影响。

### Q04 / M04：聊天历史、模型上下文和“记忆”分别是什么？

- **功能**：MySQL 会话记录、历史列表与跨轮指代。
- **实现位置**：会话列表、历史消息接口、消息持久化与上下文构建服务。
- **重点**：数据库持久记录与每次实际传给模型的消息不是一回事；Token 预算、裁剪和摘要的取舍。
- **验收**：刷新页面仍能查看历史；同一会话的“刚才那件商品”可结合上文；新会话使用独立上下文。
- **追问**：为什么不能把所有历史都塞进 Prompt？裁剪如何保留工具消息配对？摘要会不会遗失信息？
- **练习**：减少历史窗口，构造一个丢失上下文的案例并解释。

### Q05 / M05：流式响应如何实现，客户端中断后怎么办？

- **功能**：聊天逐步输出、停止生成、失败与完成状态。
- **实现位置**：HTTP 流接口、SSE 事件协议、前端 fetch 读取与 AbortController。
- **重点**：网络分片不等于完整事件；编码边界、缓冲、取消传递、消息最终状态。
- **验收**：可逐步看到文本；停止后不继续追加内容；模拟半个事件与中途失败时 UI 不误标成功。
- **追问**：何时选 WebSocket？浏览器停止读取是否必然停止供应商计费？断线重连怎样避免重复写入？
- **练习**：记录首个文本事件与完整回答的两个耗时。

### Q06 / M06：如何让 LLM 稳定返回结构化数据？

- **功能**：从用户描述提取订单号、问题类型和原因，展示售后草稿表单。
- **实现位置**：草稿提取 API、Pydantic schema、结构化输出适配与表单卡片。
- **重点**：服务商原生结构化输出、工具策略与校验；格式合法、语义正确、业务可执行需要分别判断。
- **验收**：已知字段正确显示；缺失订单号时明确追问；金额、枚举等不合法数据不会进入已确认工单。
- **追问**：JSON mode 与 schema 约束有什么不同？是否需要重试？为什么不能只写一句“输出 JSON”？
- **练习**：增加一个字段，观察前端、DTO、模型 schema 的改动链路。

## 第二阶段：可验证的知识问答

### Q07 / M07：文档为什么要切分，chunk size 和 overlap 如何选择？

- **功能**：上传合成规则文本，预览解析结果、分块和来源位置。
- **实现位置**：知识库页面、导入服务、分块器和文档版本表。
- **重点**：字符与 Token 的区别、标题边界、重叠、来源元数据、重复导入与更新失效。
- **验收**：同一规则可用两组参数切分；块可追溯原文；重复导入不产生重复有效版本。
- **追问**：块过大或过小会怎样？表格或标题怎样保留？旧规则如何从检索结果撤下？
- **练习**：构造一条跨分块边界的规则，比较 overlap 的影响。

### Q08 / M08：Embedding 如何表达语义，相似度和 Top-K 如何计算？

- **功能**：向量检索实验台：查询文本、候选分块、分数与 Top-K。
- **实现位置**：Embedding 生成与 MySQL 保存、NumPy 检索服务、实验面板。
- **重点**：向量维度、余弦/点积、归一化、模型空间、精确检索与 ANN。
- **验收**：对归一化小向量手算并核对相似度；同义查询能检索候选；维度或模型版本不匹配被拒绝。
- **追问**：维度越高是否一定更好？更换 Embedding 后哪些数据需要重建？数据库存向量和向量索引有何区别？
- **练习**：切换 K 并观察上下文规模；记录数据量增加后的检索耗时。

### Q09 / M09：RAG 的完整流程是什么，和微调如何选型？

- **功能**：店铺规则问答，答案附文档名称、版本和可点击的原文片段。
- **实现位置**：RAG 服务、Retriever 接口、上下文模板、引用卡片。
- **重点**：离线入库与在线检索生成、知识时效、私有知识、引用可追溯；RAG 与微调可以互补。
- **验收**：已录入规则能产生有依据的回答；更改规则版本后结果使用有效版本；引用 ID 可从后端证据集中校验。
- **追问**：为什么引入 RAG 后仍会出错？什么时候选微调？如何区分检索错误与生成错误？
- **练习**：对比有无检索上下文的回答，并标注哪些结论有证据。

### Q10 / M10：如何提升召回质量，混合检索和 Rerank 分别解决什么问题？

- **功能**：关键词、向量、混合召回与重排的结果对比。
- **实现位置**：MySQL ngram 关键词召回、向量召回、RRF 融合、Reranker 适配与开关。
- **重点**：同义表达、型号精确匹配、候选集合与精排；不同检索器的原始分数不能直接假定可比。
- **验收**：固定问题集显示各方案的证据排名、Recall@K/MRR 和耗时；允许出现没有收益的实测结果。
- **追问**：BM25 与 MySQL 全文检索是否同一个实现？RRF 为何用排名？Reranker 为什么通常只处理候选集？
- **练习**：分别构造“商品精确型号”和“口语化政策问题”，分析方案差异。

### Q11 / M11：RAG 为什么仍然有幻觉，证据不足时如何处理？

- **功能**：证据充足、需要澄清、知识库无答案三种响应；校验引用。
- **实现位置**：证据判定服务、回答策略与 UI 状态。
- **重点**：无关召回、过期与冲突证据、位置效应、阈值校准；相似度不是答案正确概率。
- **验收**：未录入的规则不被编造成店铺承诺；冲突规则触发澄清或人工处理提示；不存在的引用被识别。
- **追问**：提高阈值会牺牲什么？如何处理 Lost in the Middle？只靠“不要编造”的 Prompt 够不够？
- **练习**：构造一条“词很像但结论无关”的文档，观察误召回。

## 第三阶段：Agent 与业务流程

### Q12 / M12：Function Calling / Tool Calling 的执行过程是什么？

- **功能**：通过自然语言查询当前用户订单与模拟物流。
- **实现位置**：只读订单工具、参数 schema、工具执行器、订单卡片。
- **重点**：模型提出调用、后端校验执行、ToolMessage 回填；关联调用 ID、未知工具和失败处理。
- **验收**：工具返回数据库真实模拟记录；不存在的订单有明确结果；修改工具参数也不能查询其他用户订单。
- **追问**：模型会自己执行 Python 吗？工具描述为什么影响选择？用户 ID 应由模型提供还是服务端注入？
- **练习**：增加一个只读订单字段并走通工具返回到页面的链路。

### Q13 / M13：Agent 与固定 Chain 有什么区别，ReAct 循环如何停止？

- **功能**：Agent 根据问题选择查规则、查订单或组合两个工具。
- **实现位置**：`create_agent`、工具注册、执行状态卡和步数限制。
- **重点**：模型决策与确定性执行、行动与观察循环、停止条件、工具预算与错误反馈。
- **验收**：“根据我的订单判断能否退货”可组合查询；不需要工具的问题可直接回答；循环超限给出清晰状态。
- **追问**：什么情况更适合固定流程？如何避免重复调用？ReAct 与 Function Calling 有什么关系？
- **练习**：减少工具预算，观察多步任务如何失败并设计合理提示。

### Q14 / M14：LangGraph 的 State、Node、Edge 分别是什么？

- **功能**：把问题路由到规则问答、订单查询、售后草稿或澄清流程。
- **实现位置**：StateGraph、状态 schema、条件边与流程可视化面板。
- **重点**：状态更新、reducer、节点输入输出、确定性与 agentic 步骤；分支并不都需要 LLM 决策。
- **验收**：四类输入走到预期分支；能看到实际经过的节点；失败节点不会把流程误记为成功。
- **追问**：什么时候需要显式图？节点并行更新同一字段怎么办？图状态与业务数据库有什么关系？
- **练习**：增加一个不调用模型的业务条件分支。

### Q15 / M15：checkpoint、thread 和持久化恢复如何工作？

- **功能**：售后流程暂停后，刷新页面或重启后端仍可继续。
- **实现位置**：MySQL saver 适配、流程运行与恢复 API、恢复入口。
- **重点**：checkpoint 与聊天表的区别、thread 归属、节点边界、序列化、恢复重放和兼容性。
- **验收**：在等待用户输入处暂停，重启服务后恢复同一流程；另一用户不能读取该 thread；关键工具不会因恢复重复写入。
- **追问**：InMemorySaver 为什么不能跨进程恢复？恢复时哪些节点可能重跑？状态 schema 变更如何处理？
- **练习**：记录重启前后的 checkpoint 与业务状态，指出各自保存的信息。

### Q16 / M16：Human-in-the-loop 如何落地，写操作怎样保证幂等？

- **功能**：展示待确认售后草稿，用户确认后创建一笔模拟售后工单。
- **实现位置**：确认卡片、确认 API、业务事务、幂等键和操作记录。
- **重点**：模型提议与业务授权、草稿版本、状态再校验、唯一约束、事务和副作用重放。
- **验收**：未确认不建单；拒绝可结束流程；重复点击或重放请求只产生一笔工单；确认过期草稿时重新校验。
- **追问**：Prompt 能否替代服务端确认？checkpoint 是否自动保证 exactly-once？请求超时后如何判断是否已成功？
- **练习**：用并发重复提交验证唯一约束和幂等返回。

## 第四阶段：工程化与面试材料

### Q17 / M17：如何防止跨用户泄露和 Prompt Injection？

- **功能**：集中验证会话、订单、知识库和 Agent thread 的用户隔离；演示恶意文档不能提升工具权限。
- **实现位置**：统一当前用户依赖、数据范围筛选、工具白名单、受保护接口与安全回归案例。
- **重点**：身份来自认证上下文；检索前限定可访问数据；外部内容作为数据处理；工具最小权限。
- **验收**：用户 A 猜到 B 的订单号、session_id、thread_id 仍无法读取；非管理员不能上传规则；恶意规则不能触发越权工具。
- **追问**：仅在 Prompt 中写“不能越权”为什么不够？先全局 Top-K 再过滤有什么问题？日志会不会成为泄露渠道？
- **练习**：补充一个越权案例并说明它在哪一层被阻止。

### Q18 / M18：复杂 LLM 请求出错时如何定位？

- **功能**：按 trace_id 查看模型、检索、工具和节点执行轨迹。
- **实现位置**：运行列表、步骤详情、结构化日志和 MySQL 执行记录。
- **重点**：trace/run/step 关联、错误分类、耗时拆解、输入输出脱敏；LangSmith 可作为可选对照。
- **验收**：人为制造“检索为空”“工具超时”“模型失败”三类问题，能定位对应步骤与配置版本。
- **追问**：哪些日志应该保留？如何避免记录密钥和完整个人信息？模型可用但回答错时如何定位？
- **练习**：从一个失败 trace 反向找到相关会话与执行参数。

### Q19 / M19：如何降低延迟与成本，重试和并发有什么陷阱？

- **功能**：超时、重试、并发上限和上下文预算的配置与实验报告。
- **实现位置**：模型/工具适配层、异步调用、并发限制、性能实验接口。
- **重点**：首字与总耗时、阻塞调用、连接池、退避、读写重试区别；缓存必须包含权限和知识版本。
- **验收**：可控模拟故障下超时与并发限制有效；非幂等写操作不盲目重试；报告给出条件、样本数和延迟分布。
- **追问**：async 是否自动让 CPU 计算变快？什么情况下重试会放大故障？如何区分供应商延迟与本地瓶颈？
- **练习**：只调整一个参数，对比耗时、Token 与任务完成情况。

### Q20 / M20：如何评估 RAG 和 Agent，证明改动有收益？

- **功能**：固定评估集、批量运行、检索与回答质量看板及报告导出。
- **实现位置**：评估数据、运行器、评分记录与结果对比页面。
- **重点**：检索与生成分开评估；证据标签、工具与任务完成率；人工复核与 LLM-as-a-Judge 偏差。
- **验收**：保存数据集、模型、Prompt、切分和检索配置版本；用保留集比较基线与改进；同时报告质量、成本与延迟。
- **追问**：Recall@K 与 MRR 有什么差别？引用存在等于证据支持吗？评审模型的结论如何校验？
- **练习**：分析一次没有提升或出现退化的实验，提出下一步可验证假设。

## 每题面试卡模板

1. 一句话定义和适用条件。
2. 本场景中的业务触发条件。
3. 前端 → API → Service → AI / Repository 的实际调用链。
4. 为什么选这个实现，有什么取舍。
5. 一个失败案例、如何定位和修正。
6. 可复现的测试或实测指标。
7. 当前规模限制，以及扩大规模时的下一步。

面试卡在模块完成后依据真实代码填写；当前不预先编造实验结果。
