# 本地业务样本数据

生成器直接连接根目录 `.env` 配置的本地 MySQL `langchain_lab`。数据均为合成，不抓取真实个人信息，不发起模型请求，不清空表，不覆盖已有账号密码、订单、会话或文档。

## 当前数据集

默认 `biz` 数据集新增 1,000 个用户和 20,000 笔订单：

- 用户名 `sim_biz_000001`～`sim_biz_001000`；前 100 个保留无订单空态，其余覆盖普通买家与高频买家。
- 订单号 `SIM-BIZ-00000001`～`SIM-BIZ-00020000`；前缀明确表示合成数据。
- alice、bob 各追加 200 笔，其余 19,600 笔分配给新用户。原 `DEMO-A001`、`DEMO-B001` 原样保留。
- 40 类商品、4 个规格，共 160 种组合；10 种状态：待付款、待发货、已发货、运输中、派送中、已签收、已完成、已取消、售后中、已退款。
- 约 5% 高频用户分配约 30% 新用户订单，避免所有用户购买数量完全一致。种子固定，结果可复现。

本机原有 2 个用户、2 笔订单，默认生成后共 1,002 个用户、20,002 笔订单。该数量是本机实测，不表示另一台电脑的现有库也有同样基线。

## 运行

在仓库根目录执行，使用现有 E 盘环境，不新增依赖或迁移：

```powershell
# 默认只预览目标数量和状态分布，不创建账号、订单或密码文件。
uv run --locked python -X utf8 -m scripts.seed_business_data

# 实际追加；相同数据集、参数重复运行时不会增加重复记录。
uv run --locked python -X utf8 -m scripts.seed_business_data --apply

# 新的一批独立样本；不要改旧批次的参数后试图覆盖原数据。
uv run --locked python -X utf8 -m scripts.seed_business_data --dataset extra --users 100 --orders 3000 --existing-user-orders 0 --apply
```

只允许本机地址与约定开发库。新库先运行 `scripts.init_db`；每个既有账号的追加数量由 `--existing-user-orders` 指定，默认 200，设为 0 时无需 alice/bob。用户上限 5,000、订单上限 200,000。用户数或随机种子改变可能改变订单归属/内容，应该使用新的 dataset；原订单与计划冲突时脚本明确拒绝，不使用 UPDATE 或 INSERT IGNORE 遮掩差异。

同批次使用 MySQL 命名锁避免生成器并发。先计算缺失用户的独立随机盐和 scrypt 摘要，再在一个事务中批量插入用户与订单；每批 1,000 笔仅是 SQL 传输大小，任意批失败仍整批回滚。不会提前提交一部分订单。

## 登录和观察

直接重新登录 alice 或 bob，即可在订单中心看到各 201 笔记录。已有页面没有自动轮询订单，已登录时重新登录可重新加载；无需修改 `.env` 或重启后端。

新用户使用本机随机生成的数据集密码，位于已忽略的 `runtime/business-data-biz.credentials.json`；可以在编辑器中查看，不能提交或复制到交接文档。每个用户仍使用不同盐保存摘要。生成器不重置已存在用户密码。另一台电脑运行同一脚本会创建自己的密码文件，不通过 Git 同步密码或数据库数据。

可观察账号：`sim_biz_000001`（无订单）、`sim_biz_000101`（普通买家）、`sim_biz_001000`（高频买家）。查询 `SIM-BIZ-00000001` 时只有 alice 有权查看；bob 和其他用户的查询结果与不存在订单一致。生成后摘要保存在 `runtime/business-data-biz.report.json`，只包含数量、分布和凭据文件路径，不含密码或令牌。

当前订单表仅有订单编号、归属用户、商品名称和状态。此次样本覆盖这些真实字段，没有虚构金额、收货地址、创建时间、物流轨迹或完整状态流转历史，也没有为数据生成增加产品页面或接口。后续如需金额统计、按时间筛选或订单生命周期，再设计迁移与相应业务能力。
