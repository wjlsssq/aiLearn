# 聊天订单 Excel 导出

## 使用方式

重启后端并刷新前端，在聊天中提出：

- “导出 2026 年 10 月 1 日到 10 月 31 日的订单到 Excel。”
- “按付款时间导出 2026 年 10 月的耳机订单。”
- “导出 2026 年 9 月已完成的订单。”

默认按下单时间，日期包含首尾两天，使用北京时间。范围不明确时由助手追问。结果显示文件名、订单数量、过期时间和“下载 Excel”按钮；完整问答保存后才能下载，历史会话可恢复卡片。文件为生成时的数据快照，不会随业务订单更新。没有符合条件的记录时生成只有表头的有效文件，并明确显示 0 笔。

## 业务范围

- 工具名 `export_orders_excel`；输入开始/结束日期、日期口径，以及可选的精确状态和商品包含文本。身份由登录后端注入，不接受模型传 SQL、用户 ID、路径或下载 URL。
- 日期口径可选下单、付款、发货、签收；一次最多连续 366 天、5,000 笔、4MB。超过数量或大小时拒绝并提示缩小范围，不能拿聊天查询的前 50 行冒充完整导出。
- 文件包含编号、商品、状态、数量、金额、生命周期、收货和物流全部 22 个公开字段，附“导出说明”工作表。金额为人民币元、保留两位小数；实付不扣退款，未知值为空。编号、电话等作为文本保留；日期为 Excel 日期格式。用户文本不解析成公式或超链接。
- 每轮最多生成一个文件，共用现有模型/工具预算。每账号最多 10 个有效文件；文件在 24 小时后不可下载。过期后可重新导出；不提供未实现的后台任务或排队进度。

## 权限与存储

订单读取使用独立只读账号和 `agent_order_data` 视图，日期、商品、状态均绑定参数；查询强制当前用户范围并应用数据库超时。文件字节及元数据保存于 MySQL `order_exports`，不写入公开静态目录，不把二进制和订单全集发送给模型。

下载路径为 `GET /api/order-exports/{export_id}/download`，必须带 Bearer 认证；后端同时检查文件归属、有效期，以及是否已经出现在当前账号成功持久化的聊天回复中。失败、截断或取消问答产生的临时快照不可下载。下载响应禁止缓存；跨用户和过期统一返回 404。链接不包含令牌，模型不生成真实下载地址。

到期自动失去下载权限；物理数据由后续同账号导出时顺带清理，或运维定期执行下面命令。不会删除聊天历史，因此过期卡片仍会保留说明和重新导出说明。

```powershell
uv run --locked python -m scripts.cleanup_order_exports
```

## 另一台电脑升级

```powershell
# 新增 XlsxWriter；仍使用 E 盘环境和缓存。
uv sync --locked
uv run --locked alembic -c backend/alembic.ini upgrade head
```

迁移版本为 `0004_order_exports`，升级后重启后端。2026-11-18 已按用户要求重新导出全量 SQL，当前快照包含本机 Excel 快照表及数据；恢复后仍保留原到期时间。日常 Git 不自动同步新增文件或数据库内容，只有明确重导 SQL 时才包含当时的数据库快照。

## 代码与验证

- `app/ai/tools/customer_service.py` 定义工具协议，`services/agent_chat.py` 注入身份和执行预算。
- `schemas/order_export.py` 校验日期与筛选；`services/order_export.py` 管理导出规则、Excel 写入和下载授权。
- `repositories/order_export.py` 读取只读视图与持久化快照，`models/order_export.py` 和迁移维护数据库。
- 前端 `api/orderExport.ts`、`composables/useOrderExport.ts`、`ChatResult.vue` 分别负责接口、下载状态和卡片展示；组件不直接请求 HTTP。
- 后端使用真实 MySQL 与内存模型响应验证工具循环、文件内容、日期边界、超限、归属、过期、历史恢复，以及未完成问答不能下载；不请求付费模型。前端只运行格式检查与构建，交互由用户验收。
