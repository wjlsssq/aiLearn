# 产品工作台设计与调研

更新：2026-11-16。用户要求从教学工作台转为可用的企业 Agent 产品界面，调试通过代码断点完成，页面不承担课程讲解。

2026-11-17 更新：查询和资料整理已统一到聊天 Agent，独立 AI 抽屉移除；顶部面包屑/连接状态栏与右侧固定订单快捷栏也已移除，让对话占据主要工作区。具体工具范围、只读权限与启动步骤见 [智能体与统一聊天](lessons/Q13-智能体与统一聊天.md)。订单中心与规则文档仍作为业务管理页面保留。

## 调研结论

参考 [Intercom Inbox 布局](https://www.intercom.com/help/en/articles/7911926-customize-the-inbox-to-suit-you-and-how-you-work-best)：把业务导航、会话列表、主对话与可选上下文分开，保持处理会话时的业务信息可达。ShopMind 保留导航、会话列表与主对话的分工；当前没有随任务变化的侧栏内容，因此不保留固定订单列表充当上下文，未复制其品牌与具体页面。

参考 [Zendesk Agent Workspace](https://support.zendesk.com/hc/en-us/articles/4408821259930-About-the-Zendesk-Agent-Workspace)：在同一个工作空间集中呈现服务任务与上下文，减少跨页寻找信息。ShopMind 当前直接在聊天中承接查询与资料整理，结果表格和卡片留在对应消息中。

参考 [Carbon 通用模式](https://v10.carbondesignsystem.com/patterns/overview/) 对表格、对话框与导入交互的职责划分。页面级导航承担业务域切换，抽屉承担当前任务的辅助操作，提示只解释影响业务决策的限制。

最终采用浅灰白底、蓝色强调、轻边框与统一 SVG 图标。层级来自留白、字重和状态，避免用大面积教学提示与虚构数据填满页面。

## 产品信息架构

- 会话工作台：固定导航 → 可搜索会话列表 → 流式消息。移除顶部面包屑/连接状态栏和右侧固定订单栏，消息区占满剩余空间。手机上保留横向会话切换与可展开导航，订单中心和规则文档页面也能打开导航。
- 订单中心：真实账号范围内的订单列表、搜索与“在聊天中查询”操作；列表便于直接查阅业务记录，AI 查询与统计仍由聊天 Agent 统一处理。手机使用卡片，状态和操作不依赖横向滑动。
- 规则文档：新增、保存、同名版本更新、正文与历史版本查阅。分块参数由后端内部使用，不要求业务用户做 A/B 切分实验。
- 聊天查询：模型选择查询工具，返回当前账号内的订单明细或统计表格，只展示业务结果与处理状态。
- 售后资料：直接从授权会话用户原文提取，卡片展示结果与缺失项，用户可继续补充。没有虚假的确认建单按钮。
- 登录：空白账号密码表单，刷新后从受保护的 /me 恢复身份；退出撤销当前令牌。

未添加没有后端支持的看板指标、客户列表、团队分配、审批按钮或权限配置页。文档页面明确自动问答引用尚未启用。已有 MySQL 示例记录保留原始模拟标识，不改写成真实业务。

## 会话上下文与结果展示

原右侧“业务上下文”只截取当前账号订单列表的前几笔，提供查询快捷入口；它不随选中会话或本轮工具执行变化，也没有被自动传给模型。因此移除此栏不会减少 Agent 的上下文能力，订单列表仍可从订单中心查看。

真正的模型上下文由后端构造：校验当前用户与会话归属后加载允许读取的聊天历史，对历史查询结果按预算摘要，并把本轮实际工具结果交给 Agent 继续处理。单订单查询、多个订单明细和聚合统计都通过消息内的结果表格呈现；售后资料通过对应卡片呈现。界面展示实际处理结果，不把未查询的订单暗示为当前会话上下文。

## 清理范围

移除 Prompt 预览、LCEL 实验、工具协议面板、分块 A/B、首段/结束耗时演示，以及相应前端状态、API 和类型。删除只服务教学的链执行器、预览接口、对照脚本和已退役功能测试，保留模板、SSE、参数、权限、事务等业务回归。

`/api/prompts/preview`、`/api/chains/*`、`/api/tool-calling/*`、`/api/knowledge/example` 与 `/api/knowledge/preview` 已退出产品接口。业务订单查询入口为 `/api/assistant/orders`，只返回 status、answer、order、message；执行预算和参数校验仍在后端。新建 `/api/me` 与 `/api/logout`，未改变现有聊天与文档数据结构。

固定工具模拟决策、空草稿演示、工具实验报告/步骤/计数 DTO 和模拟物流文案已移除；订单服务直接返回业务结果，不再为了教学轨迹额外包装一层服务。未启用真实智能服务时订单助手/资料提取返回 503。底层 mock 仅用于真实 MySQL 自动化回归，产品界面不提供模拟入口。开发数据库初始化脚本保留供本地环境与测试，不能视为生产用户管理功能。

中文注释和历史课程文档保留为研发资料。旧讲义中的实验入口以 Git 历史 `b3bc15a` 为准，后续以业务实现为主，不重新建立教学 UI。

## 验证与实际边界

真实 MySQL 回归覆盖身份、退出撤销、订单归属、消息事务、取消和文档版本。UI 在独立端口使用隔离响应验证登录、流式增量、下一条草稿、刷新恢复、订单查询、文档保存、手机导航与卡片；未消耗真实模型额度，验收数据精确清理。

组件只注册实际使用项，中文 locale 在 App.vue 装配。生产 JS 从本次全量注册时的约 1067 KB 降到约 417 KB，gzip 从约 349 KB 降到约 148 KB；这是相同机器本次 Vite 产物对比，不是线上延迟或任务完成率结论。

当前已落地 create_agent 工具循环、受控 SQL 与查询审计，并保留每轮调用预算。图状态恢复、用户确认和幂等、组织角色、审计查询后台与正式部署仍需后续实现和验收，不能仅凭界面与只读查询宣称完整生产能力。
